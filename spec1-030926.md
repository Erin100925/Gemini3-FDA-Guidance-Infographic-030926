Technical Specification: ReguAI (Medical Device Regulatory Analysis Dashboard)
Executive Summary
ReguAI is a cutting-edge, client-side Single Page Application (SPA) designed to streamline and automate the regulatory review process for medical devices. By leveraging the advanced capabilities of the Google Gemini 3 Flash Preview model, the application ingests complex regulatory documents—such as FDA 510(k) summaries, Premarket Approval (PMA) documents, and clinical evaluation reports—and transforms them into highly structured, actionable, and visually engaging intelligence.
The system is built entirely on the frontend using React 18, TypeScript, and Vite, eliminating the need for a dedicated backend server by securely interacting with the Gemini API directly from the client environment. It features robust state management, dynamic theming (including 20 artistic painter themes), internationalization (English and Traditional Chinese), and a suite of "WOW" agentic AI features including a Regulatory Risk Radar, a Substantial Equivalence (SE) Matrix, and Simulated FDA Deficiency Letters.
1. System Architecture
1.1. High-Level Architecture
The application follows a strict Client-Side Rendering (CSR) architecture.
Presentation Layer: React 18 functional components utilizing hooks (useState, useEffect) for state management.
Styling Layer: Tailwind CSS v4 configured via Vite, utilizing native CSS variables for dynamic runtime theming.
Service Layer: A dedicated gemini.ts service module that acts as the interface between the application state and the @google/genai SDK.
Data Processing: Client-side file parsing (converting files to Base64 via FileReader) and robust JSON parsing using the jsonrepair library to handle truncated LLM outputs.
1.2. Infrastructure & Deployment
Build Tool: Vite (configured for SPA mode).
Hosting: Designed to run in containerized environments (e.g., Google Cloud Run) serving static assets.
API Gateway: Direct client-to-API communication with Google's Generative Language API. The API key is injected into the build environment via process.env.GEMINI_API_KEY.
2. Technology Stack
2.1. Core Frameworks & Libraries
React (v18.x): Core UI library. Chosen for its component-based architecture and efficient virtual DOM rendering.
TypeScript (v5.x): Provides static typing, interface definitions, and compile-time error checking, ensuring robust data contracts between the AI responses and the UI components.
Vite: Next-generation frontend tooling providing lightning-fast Hot Module Replacement (HMR) and optimized production builds.
2.2. UI & Styling
Tailwind CSS: Utility-first CSS framework. Used for responsive design, layout, and typography.
Lucide React: A comprehensive library of clean, consistent SVG icons used throughout the dashboard for visual cues.
Recharts: A composable charting library built on React components. Specifically used for rendering the interactive Polar/Radar chart in the Regulatory Risk Radar feature.
2.3. AI & Data Processing
@google/genai: The official Google Gen AI SDK used to interface with the gemini-3-flash-preview model.
jsonrepair: A critical utility library used to parse and repair malformed or truncated JSON strings. This is essential when requesting massive JSON payloads (like 100 checklist items or 30 complex infographics) that may hit the 8192 output token limit.

4. AI Integration & Prompt Engineering Strategy
The core value of ReguAI lies in its sophisticated prompt engineering and structured JSON generation using the Gemini API. All interactions are routed through src/services/gemini.ts.
4.1. Document Ingestion & Reorganization (reorganizeDocument)
Mechanism: Accepts a File object and/or raw text. If a file is provided, it is converted to a Base64 string using the browser's native FileReader API.
Multimodal Input: The Base64 string and MIME type are passed to Gemini as inlineData, allowing the model to natively process PDFs, images, or text files.
Prompt: Instructs the model to reorganize the document into a comprehensive, well-structured markdown document, preserving key facts, dates, and regulatory requirements.
4.2. Structured JSON Generation
For all analytical features, the application utilizes Gemini's responseSchema configuration to guarantee deterministic JSON outputs.
4.2.1. The 30 Infographics (generateTopics)
Objective: Extract exactly 30 distinct regulatory topics/entities.
Constraint Management: Because generating 30 complex objects requires a massive amount of tokens, the prompt explicitly includes: "IMPORTANT: Keep descriptions, summaries, and takeaways concise to ensure the response fits within output token limits."
Schema: Defined using @google/genai's Type enum, enforcing an Array of Objects with strict property requirements (id, title, summary, type, data, takeaways).
4.2.2. The 100-Item Review Checklist (generateChecklist)
Objective: Generate a granular, 100-point regulatory review checklist.
Schema: A simple Array of Strings.
4.2.3. Regulatory Risk Radar (generateRiskRadar)
Objective: Perform a risk assessment across 5 hardcoded categories (Clinical Data, Biocompatibility, Software/Cybersecurity, Electrical/EMC, Performance Testing).
Scoring Logic: The prompt instructs the model to score each category from 1 to 10, where 10 indicates high risk or missing information.
4.2.4. Substantial Equivalence (SE) Matrix (generateSEMatrix)
Objective: Identify the predicate device and compare it against the subject device.
Categorization: The schema explicitly enforces that the equivalence field must be exactly one of three strings: 'Identical', 'Similar', or 'Different'. This allows the UI to reliably apply color-coded badges (Green, Blue, Amber).
4.2.5. Simulated FDA Deficiency Letter (generateDeficiencyLetter)
Objective: Act as an FDA Lead Reviewer and generate an RTA/AI letter.
Structure: Requires a date, reviewer name, and an array of deficiencies, each containing a description and a specific "Requested Action".
4.3. Resilience & Error Handling (safeParseJSON)
Large Language Models, even with schema enforcement, can occasionally truncate outputs if they hit the maxOutputTokens limit (set to 8192). To prevent the application from crashing with SyntaxError: Unterminated string in JSON, a custom wrapper is used:
code
TypeScript
function safeParseJSON(text: string, fallback: any) {
  if (!text) return fallback;
  try {
    return JSON.parse(text);
  } catch (error) {
    console.warn('JSON parse error, attempting repair...');
    try {
      const repaired = jsonrepair(text);
      return JSON.parse(repaired);
    } catch (repairError) {
      return fallback;
    }
  }
}
This ensures that if the AI generates 28 out of 30 infographics before running out of tokens, the application will successfully render the 28 items rather than failing entirely.
5. User Interface & Component Architecture
5.1. Theming Engine
The application features a highly dynamic theming engine controlled via CSS variables in index.css.
Base Variables: --bg-color, --text-color, --primary-color, --secondary-color, --accent-color, --card-bg, --border-color.
Dark Mode: Toggled by adding the .dark class to the <html> element, which overrides the base variables with dark-mode equivalents.
Painter Themes: 20 distinct artistic themes (e.g., .theme-van-gogh, .theme-monet, .theme-picasso) that inject specific color palettes inspired by famous artists. These classes are dynamically appended to the root element based on user selection in the ThemeControls component.
5.2. View Routing (Step-based)
Navigation is handled via a simple state machine (state.step):
upload: Renders the DocumentInput component. Handles drag-and-drop file uploads and raw text pasting.
review: Renders the MarkdownEditor component. Displays the reorganized markdown document and provides the "Generate All Features" trigger.
dashboard: Renders the Dashboard component, the core analytical interface.
5.3. Dashboard Component (Dashboard.tsx)
The Dashboard is a complex, tabbed interface that conditionally renders the AI-generated data.
Tab Navigation: Uses a custom TabButton component to switch between Infographics, Checklist, Risk Radar, SE Matrix, FDA Letter, and Questions.
Risk Radar Visualization: Utilizes recharts to render a RadarChart. The chart is fully responsive (ResponsiveContainer) and maps the category to the angle axis and the score to the radius axis.
SE Matrix Table: A responsive HTML table that iterates through the comparisons array, applying dynamic Tailwind classes to the equivalence badges based on their value.
FDA Letter View: Styled with a serif font (font-serif) and formal layout to mimic an official government document.
6. Export & Reporting Engine
A critical feature of ReguAI is the ability to export the generated intelligence. This is handled entirely client-side within the Dashboard component.
6.1. Markdown Export (handleDownloadMarkdown)
Iterates through all state objects (topics, riskRadar, seMatrix, deficiencyLetter, checklist, questions).
Constructs a formatted Markdown string using template literals.
Creates a Blob with type: 'text/markdown', generates an Object URL, and programmatically clicks a hidden anchor <a> tag to trigger the download.
6.2. HTML Export (handleDownloadHTML)
Similar to the Markdown export, but constructs a complete HTML document string.
Injects inline CSS (<style>) to ensure the downloaded file retains basic formatting (fonts, borders, table layouts) independently of the application.
Creates a Blob with type: 'text/html' and triggers the download.
6.3. PDF / Print Export (handleDownloadPDF)
Invokes the browser's native window.print() dialog.
Print Stylesheet (@media print): Located in index.css, this is crucial for a clean PDF output.
Forces background-color: white and color: black.
Hides UI controls (buttons, tabs) using .print\:hidden.
Forces all tabs to render simultaneously using .print\:block (so the PDF contains the entire report, not just the active tab).
Removes shadows and borders (.print\:shadow-none, .print\:border-none) for a cleaner paper look.
Enforces page breaks (page-break-after: always) after major sections to prevent awkward content splitting.
7. Security & Performance Considerations
7.1. Security
API Key Protection: The GEMINI_API_KEY is injected at build time and is never exposed in the source code repository. Because this is a client-side application, the key is visible in network requests; however, in the AI Studio environment, this is managed by the platform's secure proxy layer.
Data Privacy: Documents are processed entirely in memory and sent directly to the Gemini API. No data is persisted to a database or local storage, ensuring that sensitive regulatory documents are not retained.
7.2. Performance
Lazy Rendering: The dashboard only renders the active tab's content (unless printing), reducing DOM nodes and improving render performance.
Concurrent Generation: While currently implemented sequentially for stability and to prevent rate-limiting, the architecture supports parallelizing the generateTopics, generateChecklist, etc., using Promise.all() in future iterations.
Token Optimization: Prompts are strictly engineered to request concise data, minimizing payload size and processing time.
8. Future Scalability & Extensibility
The current architecture provides a robust foundation for future enhancements:
Backend Migration: If persistence (saving reports, user accounts) is required, the gemini.ts service can be easily migrated to a Node.js/Express backend, converting the frontend calls to standard fetch requests.
Real-time Collaboration: Integrating WebSockets (e.g., Socket.io) or CRDTs (e.g., Yjs) would allow multiple regulatory affairs specialists to edit the markdown and review the dashboard simultaneously.
FDA Database Integration: The application could be extended to query public FDA databases (e.g., MAUDE, 510(k) premarket notification database) via APIs to automatically cross-reference the AI's Substantial Equivalence claims.
Multi-Agent Workflow: Implementing a multi-agent system where one AI model generates the content, and a secondary "Critic" AI model reviews the output for regulatory compliance and hallucinations before presenting it to the user.
