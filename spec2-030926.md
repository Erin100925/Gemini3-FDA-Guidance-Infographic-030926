Technical Specification: Agentic AI System for Medical Device Premarket Review Infographic Generation (WOW UI) - v2.0
1. Executive Summary
This document serves as the comprehensive technical specification for version 2.0 of the Agentic AI System for Medical Device Premarket Review Infographic Generation. Designed with a "WOW UI" philosophy, this application is a next-generation, multimodal, and multilingual AI platform tailored specifically for medical device professionals, regulatory affairs specialists, and compliance officers.
Building upon the robust foundation of v1.0, this upgraded system introduces unprecedented levels of user control, exportability, and advanced AI capabilities. The system allows users to input raw, unstructured medical device premarket review guidance, 510(k) summaries, or regulatory notes. Utilizing advanced Large Language Models (LLMs) via the Gemini API, the system restructures the input into organized markdown, extracts up to 30 critical regulatory topics, generates detailed code-driven infographic specifications for each topic, and compiles a comprehensive compliance review checklist.
1.1. Key Upgrades in v2.0
Granular Agent Configuration: Users can now explicitly select the underlying LLM (gemini-2.5-flash or gemini-3-flash-preview) and modify the exact prompt templates for each individual agent in the pipeline (Transformer, Topic Extractor, Infographic Planner, Checklist Generator).
Universal Export Engine: Users can seamlessly download their generated artifacts in three formats: a standalone interactive HTML bundle, a clean Markdown document, or a styled PDF report that preserves the selected "WOW" aesthetics.
Three New "WOW AI" Features:
Regulatory Gap Radar: A real-time, AI-generated multidimensional radar chart highlighting compliance blind spots.
Time-Travel Regulatory Diffing: An AI engine that compares legacy and new guidance documents to generate "Delta Infographics."
Voice-to-Infographic (Multimodal): Direct audio ingestion of regulatory strategy meetings, transcribed and transformed instantly into the 30-topic infographic pipeline.
The user interface remains visually stunning and highly interactive, featuring real-time theming with Light/Dark modes, bilingual support (English, Traditional Chinese, or Dual), and 20 unique visual styles inspired by famous painters.
2. System Architecture Overview
The application is built as a Single Page Application (SPA) using a modern, high-performance frontend stack. It relies heavily on client-side processing for UI state management while offloading heavy natural language processing and data extraction tasks to the Gemini API.
2.1. Technology Stack
Core Framework: React 19 (Functional Components & Hooks)
Build Tool: Vite 6.x
Language: TypeScript (Strict Mode)
Styling: Tailwind CSS v4 (Utility-first CSS)
Animations: Framer Motion (Declarative animations and transitions)
Icons: Lucide React (Consistent, scalable SVG iconography)
Markdown Rendering: React-Markdown
AI Integration: @google/genai SDK
Export Libraries: html2canvas and jspdf (for PDF generation), jszip (for HTML bundling).
Utility Libraries: clsx and tailwind-merge for dynamic class name composition.
2.2. Architectural Pattern
The system follows a Container-Presenter pattern combined with a Monolithic State Object approach at the root level.
App.tsx acts as the primary state container and theme orchestrator.
Child components (Sidebar, Dashboard, InputPanel, OutputPanel, AgentConfigModal) act as presenters that receive state and state-mutating functions via props.
External services (geminiService.ts, exportService.ts) encapsulate all asynchronous API calls and file generation logic, keeping the UI components pure and focused on rendering.

4. Theming Engine and "WOW UI" Aesthetics
The "WOW UI" is driven by a dynamic theming engine that manipulates CSS Custom Properties (variables) at the :root level. This allows for instantaneous, application-wide visual updates without requiring component re-renders.
4.1. Light and Dark Mode
The application supports a standard Light/Dark mode toggle. This is implemented by adding or removing the .dark class on the <html> element, which Tailwind CSS uses to apply dark: variant utility classes. Base background and text colors are injected as CSS variables:
--bg-primary: The main background color (White in light mode, Slate-900 in dark mode).
--bg-secondary: The secondary background for sidebars and panels (Slate-50 in light mode, Slate-800 in dark mode).
--text-primary: High-contrast text color.
--text-secondary: Muted text color for subtitles and metadata.

6. AI Integration & Customizable Agentic Workflow
The core intelligence of the application is powered by the @google/genai SDK. In v2.0, the hardcoded API calls are replaced with a dynamic prompt injection system.
6.1. Dynamic Prompt Injection Engine
When an action is triggered (e.g., "Extract Topics"), the geminiService.ts retrieves the current AgentConfig from the state. It performs a string replacement on the promptTemplate before sending the request to the Gemini API.
code
TypeScript
// Example of dynamic prompt injection
const config = state.agentConfigs['extractor'];
let finalPrompt = config.promptTemplate
  .replace('{{input_text}}', state.structuredMarkdown)
  .replace('{{language}}', state.language);

const response = await ai.models.generateContent({
  model: config.model, // User-selected model
  contents: finalPrompt,
  config: {
    responseMimeType: "application/json",
    responseSchema: topicSchema,
    temperature: config.temperature
  }
});

7. The Three New "WOW AI" Features
To elevate the platform from a standard extraction tool to an indispensable regulatory intelligence suite, three advanced "WOW" features have been engineered.
7.1. WOW Feature 1: AI-Powered "Regulatory Gap Radar"
Concept: Regulatory professionals often need to know what is missing just as much as what is present. The Gap Radar provides an instant visual heuristic of the document's comprehensiveness.
Technical Implementation:
Agent: A new RadarAgent is introduced.
Prompt: The LLM is instructed to evaluate the structuredMarkdown against five standard regulatory pillars: Clinical Evaluation, Quality Management (QMS), Cybersecurity, Usability/Human Factors, and Post-Market Surveillance (PMS).
Output Schema: The LLM returns a JSON object scoring each pillar from 0 to 100, along with a 1-sentence justification.
UI Rendering: The OutputPanel features a new "Radar" tab. It uses an SVG-based radar chart (or a library like Recharts) to plot the 5 axes. The chart is dynamically colored using the current painterStyleId's primary and accent colors. If a score is below 40, a pulsating warning icon appears next to that axis, drawing immediate attention to the regulatory gap.
7.2. WOW Feature 2: "Time-Travel" Regulatory Diffing
Concept: When regulatory bodies release draft updates (e.g., transitioning from EU MDD to EU MDR), the most critical question is "What changed?" This feature generates a specific "Delta Infographic."
Technical Implementation:
Input: The InputPanel is updated to allow a "Compare Mode" where the user can paste two documents (Legacy Guidance and New Guidance).
Agent: The DifferAgent uses gemini-3-flash-preview to perform semantic diffing.
Prompt: Compare Document A (Legacy) and Document B (New). Identify the top 5 material changes in regulatory requirements. Output as a JSON array of 'Delta Objects' containing: old_rule, new_rule, impact_level, and suggested_action.
UI Rendering: The output is rendered as a specialized "Before & After" timeline infographic. Framer Motion is used to create a sliding toggle that lets the user visually swipe between the old state and the new state, applying the painter styles to differentiate the eras (e.g., sepia tones for legacy, vibrant colors for new).
7.3. WOW Feature 3: Voice-to-Infographic (Multimodal Ingestion)
Concept: Regulatory strategy is often discussed in meetings. This feature allows a user to dictate their strategy or upload a meeting recording, bypassing manual typing entirely.
Technical Implementation:
Audio Capture: The InputPanel utilizes the browser's MediaRecorder API to capture microphone input, storing it as a Blob in AppState.audioBlob.
Agent Integration: The system leverages the @google/genai SDK's native multimodal capabilities. Instead of sending text, the system sends the audio data as an inlineData part.
Pipeline:
The audio is sent to gemini-2.5-flash with the prompt: Transcribe this regulatory meeting and format it into structured markdown.
The resulting markdown is automatically piped into the structuredMarkdown state.
The system automatically triggers the Topic Extractor and Infographic Planner.
WOW Effect: The user speaks into the app, and within seconds, a complete, bilingual, 30-topic interactive infographic dashboard materializes on the screen.
8. Universal Export & Download Engine
A critical requirement for enterprise tools is the ability to export artifacts for offline use, sharing, or official documentation. The system implements a robust, client-side export engine triggered from the Dashboard header.
8.1. Markdown Export (.md)
Mechanism: The simplest export. The exportService.ts concatenates the structuredMarkdown, the 30 topics (formatted as markdown headers and bullet points), the infographic specs (formatted as code blocks or tables), and the checklist.
Execution: Creates a Blob with MIME type text/markdown, generates an object URL via URL.createObjectURL(), and triggers a hidden <a> tag download.
8.2. PDF Export (.pdf)
Mechanism: To preserve the "WOW UI" aesthetics (the painter styles, the bilingual typography, the layout), the system uses a combination of html2canvas and jspdf.
Execution:
A hidden, print-optimized div is temporarily rendered in the DOM containing all artifacts expanded (no tabs).
html2canvas takes a high-resolution screenshot of this DOM node.
jspdf takes the resulting canvas image and paginates it into a standard A4 PDF document.
The PDF retains the exact colors of the selected painter style (e.g., the Van Gogh blues and yellows).
8.3. Interactive HTML Bundle Export (.zip)
Mechanism: This fulfills the WebpageBundlePlan requirement of the original skill. It packages the entire output into a standalone, zero-dependency webpage.
Execution:
The system generates a static index.html string. This HTML includes a lightweight, vanilla JavaScript rendering engine and inline CSS.
The AppState (topics, specs, checklist) is serialized into a data.js file attached to the window object.
The jszip library is used to bundle index.html and data.js into a single infographics_bundle.zip file.
When the user extracts and opens index.html locally, they see a fully interactive, styled dashboard of their 30 infographics, completely independent of the main React application.
9. Bilingual Support Architecture
The application is designed from the ground up to support global regulatory teams, specifically focusing on English and Traditional Chinese (繁體中文).
UI Localization: The Language state (en, zh, dual) dictates how data is rendered.
Data Model Design: Instead of relying on real-time translation during rendering, the AI is instructed to generate bilingual fields upfront (e.g., title_en and title_zh).
Rendering Logic:
If state.language === 'en', only title_en is shown.
If state.language === 'zh', only title_zh is shown.
If state.language === 'dual', title_en is shown as the primary header, with title_zh rendered directly below it in a muted, secondary style. This is crucial for regulatory contexts where precise terminology in both languages must be compared.
10. Security, Privacy, and Compliance Considerations
Given the sensitive nature of medical device premarket reviews (e.g., unreleased 510(k) data, proprietary algorithms, clinical trial results), security is paramount.
10.1. API Key Management
In this prototype, the Gemini API key is injected via Vite's define configuration (process.env.GEMINI_API_KEY).
Production Warning: In a true production environment, exposing the API key to the client-side bundle is a severe security risk. The architecture must be migrated to a Full-Stack model (e.g., Next.js or Express + Vite) where API calls are proxied through a secure backend server.
10.2. Data Privacy & Audio Handling
Currently, all document and audio processing happens via API calls to Google's Gemini models. Users must be informed of the data sharing policies of the underlying LLM provider.
For the Voice-to-Infographic feature, audio blobs are processed entirely in memory and sent directly to the API via HTTPS. No audio files are saved to local storage or a database, ensuring ephemeral processing of potentially confidential meeting recordings.

State Management: As the application grows to include custom prompts and multiple document diffs, will the monolithic AppState object become a performance bottleneck? Should we transition to Zustand or Redux Toolkit?
Offline Capabilities: Can the standalone HTML export bundle be configured to work entirely offline, or will it require external CDN links for fonts and icons?
AI & Prompt Engineering
Prompt Injection Vulnerabilities: Now that users can edit the AgentConfig prompt templates, how do we sanitize the inputs to prevent malicious prompt injection that could break the JSON schema requirements?
Model Fallbacks: If the user selects gemini-3-flash-preview but the API experiences downtime or rate limits, should the system automatically fall back to gemini-2.5-flash, and how is this communicated in the UI?
Diffing Accuracy: For the "Time-Travel Regulatory Diffing" feature, how do we ensure the LLM doesn't hallucinate changes that didn't actually occur between Document A and Document B?
Radar Calibration: How do we calibrate the AI for the "Regulatory Gap Radar" so that a score of "40/100" in Cybersecurity means the same thing across different types of medical devices (e.g., SaMD vs. a physical scalpel)?
Bilingual Nuance: Are there specific medical device regulatory terms (e.g., "Notified Body", "Premarket Approval") that the LLM mistranslates? Should we implement a custom glossary injection into the user-editable prompts?
User Experience (UX) & "WOW UI"

Accessibility (a11y) in PDFs: When exporting to PDF, html2canvas flattens text into an image. How can we ensure the resulting PDF remains screen-reader accessible for compliance purposes?
Mobile Responsiveness: How should the new "Regulatory Gap Radar" and "Time-Travel Diff" UI components be rendered on mobile devices without losing legibility or interactive fidelity?
Audio Feedback: During the Voice-to-Infographic recording phase, what visual feedback (e.g., a waveform visualizer) should be provided to assure the user that their microphone is capturing data correctly?
Micro-interactions: What specific Framer Motion animations should be added to the Infographic cards to make the transition from "Spec" to "Rendered Chart" feel magical?
Regulatory & Compliance Domain

Regulatory Disclaimers: Should the UI and the exported PDFs enforce a mandatory, non-dismissible disclaimer stating that AI-generated checklists and Gap Radars do not constitute formal legal or regulatory advice?
